Keep internal apps running on Windows.

Point Keeprun at a folder. It detects Node, .NET or Python, runs the app under a Windows service, restarts it when it crashes and starts it again after a reboot. Logs, environment and ports in one place.

What it does

Detects how to run it

npm, pnpm, yarn and bun scripts, .NET projects and published builds, Python with venv, uvicorn, Flask and Django. Or any command line.

Restarts on crash

Backoff from 1 second up to 60. After repeated crashes the app is marked Failed instead of looping forever.

Survives reboots

A Windows service starts the apps that were running. Apps you stopped stay stopped.

Kills the whole tree

Each app runs in a Job Object. Stop ends every child process, so ports are free for the next start.

Logs and health

Live output with search, CPU, memory, listening ports and an event history of starts, stops and crashes.

Secrets encrypted

Environment values marked secret are stored with Windows DPAPI and masked in the UI.

Tasks on demand

Migrations, seeds and installs are saved as tasks and run when you choose, with the app's environment.

Built for IT

Silent MSI for Intune and SCCM, a CLI for scripts, a local API, and update checks you can turn off by policy.

Same thing from a terminal

# Add the app in the current folder and start it
keeprun add --start

# Status, CPU, memory and ports of every app
keeprun list

# Follow logs, run a migration
keeprun logs hr-portal -f
keeprun run hr-portal db:migrate
