Keep internal apps running on Windows.

Point Keeprun at a folder. It detects Node, .NET or Python, runs the app under a Windows service, restarts it when it crashes and brings it back after a reboot. No Docker, no WSL, no Hyper-V: your app runs as a normal Windows process, with logs, environment, ports and health in one place.

Why Keeprun

Most internal apps run on a .bat file and hope.

Today

  • A script in a Startup folder, a Scheduled Task, or a service wrapper someone set up years ago.
  • A crash goes unnoticed until users call the help desk.
  • Logs are in a console window on a server nobody logs in to.
  • Connection strings sit in plain text next to the code.
  • One person knows how it all fits together.

With Keeprun

  • {{icon:check}} One Windows service supervises every app on the machine.
  • {{icon:check}} Apps run as normal Windows processes. No Docker, WSL or Hyper-V to install or license.
  • {{icon:check}} Crashes restart with backoff, and each one is recorded.
  • {{icon:check}} Live logs with search, from the desktop app or the CLI.
  • {{icon:check}} Secrets encrypted with Windows DPAPI and masked in the UI.
  • {{icon:check}} Every app is listed with its folder, command, port and history.

Features

What you get on day one

{{icon:folder-search}}

Detects how to run it

npm, pnpm, yarn and bun scripts, .NET projects and published builds, Python with venv, uvicorn, Flask and Django. Or any command line.

{{icon:rotate-ccw}}

Restarts on crash

Backoff from 1 second up to 60. After repeated crashes the app is marked Failed instead of looping forever.

{{icon:power}}

Survives reboots

Apps that were running start with the server. Apps you stopped stay stopped.

{{icon:list-tree}}

Ends the whole process tree

Each app runs in a Windows Job Object. Stop ends every child process, so the port is free for the next start.

{{icon:scroll-text}}

Logs and events

Live output with search and an error filter, rotated by size. A history of starts, stops, crashes and config changes.

{{icon:gauge}}

Health at a glance

CPU, memory, process count, uptime and the TCP ports each app actually listens on.

{{icon:network}}

Ports without surprises

Set a port per app. Keeprun refuses two apps on one port and tells you which process holds a busy one.

{{icon:list-checks}}

Tasks on demand

Migrations, seeds and installs are saved as tasks and run when you choose, with the app's folder and environment.

{{icon:lock-keyhole}}

Encrypted secrets

Environment values marked secret are stored with DPAPI, masked in the UI and kept out of Keeprun's own logs.

How it works

Three steps from folder to running app

  1. 1

    Install once per server

    The MSI installs the agent as a Windows service, the desktop app and the keeprun CLI.

    msiexec /i Keeprun.msi /qn
  2. 2

    Add an app folder

    Keeprun reads package.json, the .csproj or the venv, suggests the command and imports .env.

    keeprun add --cwd D:\apps\hr --start
  3. 3

    It stays running

    The service starts it, restarts it after a crash and starts it again after a reboot.

    keeprun list

Security

Built to pass a security review

Keeprun runs on your servers and talks to nothing outside them unless you allow update checks. Every choice below is documented in the security model.

  • {{icon:network}}
    Local onlyThe API listens on 127.0.0.1. Nothing is exposed to the network.
  • {{icon:key-round}}
    Token accessThe API token is readable only by SYSTEM, Administrators and the Keeprun Users group.
  • {{icon:lock-keyhole}}
    Secrets with DPAPISecret values are encrypted at rest with Windows DPAPI.
  • {{icon:eye-off}}
    No telemetryNo usage data, no accounts, no cloud service.
  • {{icon:badge-check}}
    Signed updatesInstallers are verified against a signing key before they run, and only after administrator approval.
  • {{icon:shield-check}}
    Policy controlTurn update checks off or point them at an internal mirror with Group Policy.

For IT

Deploy to every machine the way you deploy everything else

The MSI installs silently, repairs, upgrades in place and keeps apps, logs and settings across versions. Settings are MSI properties, so one command line covers the fleet.

Deployment guide {{icon:arrow-right}}
{{icon:terminal}} PowerShell, as Administrator
# Install, set the API port, turn off update checks
msiexec /i Keeprun_{{VERSION}}_x64_en-US.msi /qn `
  KEEPRUN_PORT=7171 `
  KEEPRUN_DISABLE_UPDATES=1

# Grant a user the desktop app and CLI
net localgroup "Keeprun Users" CONTOSO\jdoe /add
PropertyEffect
KEEPRUN_PORTAgent API port
KEEPRUN_USERUser who may use the desktop app
KEEPRUN_DISABLE_UPDATESNo update checks
KEEPRUN_UPDATE_URLInternal update mirror

For developers

Stop babysitting your dev servers

Add your project once and Keeprun keeps the dev server, API and workers running in the background. No terminal tab per process, and no restarting them after a crash or a reboot.

Your terminal stays free for the work itself, such as a coding agent like Claude Code. It can read the logs and restart the app with the CLI, so it never ties up a shell waiting on a server.

{{icon:terminal}} Your terminal
> keeprun add web --cwd C:\src\shop --start
> keeprun add api --cwd C:\src\shop\api --start

# Back to work. Check on them when you need to.
> keeprun logs api -n 50
> keeprun restart api

FAQ

Questions IT teams ask

Which account do apps run as?

The agent runs as LocalSystem and apps run under it, like other Windows services. Running each app as its own account is on the roadmap.

How is it different from NSSM or WinSW?

NSSM and WinSW wrap one app in one Windows service, configured by hand. Keeprun is one service that supervises every app on the machine, detects how to run Node, .NET and Python apps, and gives you live logs, health and crash history in a desktop app and a CLI.

Can I use it instead of PM2 on Windows?

Yes. Keeprun covers what PM2 is usually used for, restart on crash, start on boot and logs, and runs as a real Windows service, so it starts with the machine without a startup script. It also runs .NET, Python and any other command, not only Node.

Does it replace IIS?

No. Keeprun runs the app process. Put IIS, nginx or a load balancer in front of it if you need TLS, host names or several instances.

What happens if the agent itself crashes?

Windows restarts the service after 5, 10 and 30 seconds. Each app runs in a Job Object tied to the agent, so no orphaned processes are left holding ports, and apps that were running start again.

Do I need Docker? Can it run containers?

No Docker is needed. Keeprun runs your app directly as a Windows process, so there is no Docker Desktop license, no WSL and no Hyper-V, and it works on VMs without nested virtualization. Keeprun does not manage containers itself. If Docker is installed, it can supervise a command such as docker compose up like any other command.

Does it need internet access?

No. The only outbound request is the optional update check to keeprun.app, which you can turn off or point at an internal mirror.

Which Windows versions are supported?

Any 64-bit Windows from Windows 10 and Windows Server 2016 on: Windows 10 and 11, Windows Server 2016, 2019, 2022 and 2025. Use it on a developer laptop or a production server. Windows 7 and 8 are not supported, because the desktop app needs WebView2.

Is it free for commercial use?

Yes. Keeprun is open source under the Apache 2.0 license.
